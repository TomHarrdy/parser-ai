# Техническое задание: AI-агент для мониторинга упоминаний бренда (MCP Architecture)

## 1. Цель проекта
Разработать автономную систему мониторинга упоминаний компании в интернете, основанную на агентной архитектуре (Agentic Workflow). Система использует LLM в качестве ядра для принятия решений, анализа и маршрутизации, а для доступа к веб-ресурсам применяет специализированные инструменты (MCP-серверы и AI-first API).

Такой подход позволяет отказаться от поддержки самописных парсеров, обхода блокировок (капч) и использовать бесплатные лимиты современных AI-сервисов.

## 2. Архитектура решения

Вместо жестко закодированных скриптов-парсеров (workers), используется AI-оркестратор (например, скрипт на Python с использованием LangChain/LangGraph, либо low-code платформа типа n8n), который обращается к LLM (Claude 3.5 Sonnet, GPT-4o-mini или локальная модель). Агенту выдаются «инструменты» (Tools / MCP-серверы) для взаимодействия с внешним миром.

### 2.1. Используемые инструменты (Tools / MCP)
1. **Tavily Search (MCP/API):** Инструмент для поиска по открытому вебу (СМИ, блоги, форумы). Специализируется на выдаче чистого контента для LLM.
2. **Apify (MCP/API - Actors):** Инструмент для извлечения структурированных данных со сложных платформ (Яндекс.Карты, 2ГИС, ВКонтакте, Telegram), где обычный поиск не работает из-за закрытых API или JS-рендеринга.
3. **Firecrawl (MCP/API):** Инструмент для глубокого парсинга конкретных URL (когда Tavily нашел ссылку на форум, а агенту нужно прочитать всю ветку обсуждения). Превращает любой сайт в чистый Markdown.

## 3. Алгоритм работы (Pipeline)

Система запускается по расписанию (cron) — например, каждый час.

### Шаг 1. Сбор данных (Retrieval)
Агент последовательно или параллельно вызывает свои инструменты:
- Вызов Tavily: Search: «Упоминания компании [Бренд] за последние 24 часа» → Возвращает массив свежих статей и новостей.
- Вызов Apify (VK Actor): Запускает парсер по ключу [Бренд] в ВКонтакте → Возвращает посты и комментарии.
- Вызов Apify (Yandex Maps Actor): Запрашивает отзывы по конкретному ID компании → Возвращает последние отзывы.

### Шаг 2. Дедупликация и Фильтрация
- Полученные данные (тексты, ссылки, авторы) прогоняются через базу данных (PostgreSQL).
- Если URL или уникальный ID отзыва уже есть в базе — запись игнорируется.
- Для проверки дублей текстов без уникальных ссылок (например, перепечатки новостей) используется проверка по хэшу текста.

### Шаг 3. AI-Анализ (Reasoning & Extraction)
Для каждого *нового* уникального упоминания LLM выполняет задачу (Prompt):
> «Прочитай следующий текст упоминания о компании [Бренд].
> 1. Определи тональность (positive, negative, neutral).
> 2. Выдели основную причину, если это жалоба или похвала.
> 3. Напиши краткое summary в 1-2 предложениях.
> Верни ответ в формате JSON.»

*Примечание: Если исходный текст находится по ссылке, которую сложно прочитать в сниппете Tavily, Агент сам вызывает инструмент Firecrawl для скачивания полного Markdown-кода страницы.*

### Шаг 4. Сохранение и Уведомление
- Обогащенные данные (с тональностью и summary) сохраняются в PostgreSQL.
- Если тональность определена (особенно Негатив) — формируется HTTP-запрос к Telegram Bot API для отправки алерта в чат техподдержки/маркетинга.

### Шаг 5. Еженедельный дайджест (Weekly Digest)
Раз в неделю агент делает SQL-выборку всех записей за 7 дней, загружает их в контекст LLM и просит сгенерировать аналитический отчет: тренды недели, главные темы жалоб, общая статистика. Отчет отправляется в Telegram.

## 4. Стек технологий

- **Оркестрация Агента:** Python 3.12 + LangChain / LangGraph (или n8n для визуального программирования).
- **LLM Core:** OpenAI API (gpt-4o-mini — дешево и быстро) или Anthropic API (Claude 3.5 Haiku).
- **Интеграции (Tools):** Tavily API, Firecrawl API, Apify API. У всех есть нативная поддержка в виде MCP-серверов или интеграций LangChain.
- **База данных:** PostgreSQL (SQLAlchemy).
- **Рассылка:** Telegram Bot API (aiogram).
- **Инфраструктура:** Docker, Docker Compose.

## 5. Модель данных (БД)

Таблица **mentions** (Упоминания):
- `id` (UUID)
- `url` (Ссылка на источник)
- `source_type` (Enum: web, news, vk, yandex_maps, etc.)
- `raw_text` (Исходный текст)
- `ai_summary` (AI-выжимка)
- `sentiment` (Enum: positive, negative, neutral)
- `is_alert_sent` (Boolean — отправлено ли в ТГ)
- `created_at` (Timestamp)

## 6. Экономика проекта (Расчетные затраты)

Ориентировочные затраты для небольшой/средней компании:
- Сервер (VPS): ~500-1000 ₽ / мес.
- Tavily: Бесплатно (до 1000 поисков в месяц).
- Firecrawl: Бесплатно (до 1000 скрапов в месяц).
- Apify: Бесплатно (до $5 использования Actors в месяц, далее копейки за запуск).
- LLM API (Токены): ~200-500 ₽ / мес в зависимости от объема текстов.
- **Итого:** ~1 500 ₽ в месяц за систему энтерпрайз-уровня.

## 7. Этапы реализации MVP

1. Регистрация ключей: Получить API-ключи Tavily, Firecrawl, Apify, OpenAI/Anthropic, Telegram Bot.
2. Настройка БД: Развернуть PostgreSQL, накатить миграции с таблицей mentions.
3. Разработка Агента (Python/n8n): Подключить инструменты к LLM, настроить логику вызова (сначала Tavily + Apify → потом LLM).
4. Настройка промптов: Отладить системный промпт LLM для корректного возврата JSON с sentiment и summary.
5. Интеграция Telegram: Настроить отправку мгновенных уведомлений.
6. Тестирование и деплой: Завернуть в Docker, запустить по расписанию на сервере (например, через APScheduler или cron).
